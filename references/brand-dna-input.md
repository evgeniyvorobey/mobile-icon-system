# Brand DNA Input

Brand DNA is the visual language icons must inherit. Without it, icons drift into generic Material/SF lookalikes and lose brand cohesion. This file defines what Brand DNA captures, the three input modes, and the canonical structure of a `brand-dna.md` artifact.

## What Brand DNA Captures

Six dimensions, all mandatory:

1. **Geometric alphabet** — primitives the brand uses (e.g., circle, square, arc, cut diagonal)
2. **Stroke language** — weight, contrast, modulation rules
3. **Terminal style** — how strokes end (square / round / cut / wedge)
4. **Corner treatment** — outer corner radius logic, inner corner logic
5. **Color logic** — how colors are assigned (tint vs duotone, accent rules)
6. **Optical correction principles** — how the brand handles overshoot, balance, weighting

These are not aesthetic preferences. They are construction rules that downstream icons must follow to feel like one family.

## Three Input Modes

The skill is self-contained — none of these modes depend on any other skill or external generator. Brand DNA can come from a hand-written file, an extracted analysis of brand assets, or a guided conversation with the user.

### Mode 1: Read existing `brand-dna.md`

If a `brand-dna.md` file already exists in the project — written by hand, generated by another tool, or carried over from a sibling project — read it first. It does not matter who or what created the file; the skill treats any well-formed `brand-dna.md` as authoritative.

Search order:
- `./brand-dna.md`
- `./brand/brand-dna.md`
- `./.claude/brand-dna.md`
- `./design-system/brand-dna.md`
- `./docs/brand-dna.md`

Validate the file against the canonical structure below — every Brand DNA dimension must be present. If any dimension is missing or ambiguous, flag it and either extract that dimension from project assets (Mode 2) or ask the user (Mode 3) for the missing piece. Do not silently fill gaps.

State the source in the response (`Brand DNA source: brand-dna.md @ ./brand/brand-dna.md`).

### Mode 2: Extract from project assets

When no `brand-dna.md` exists but logo / brand assets are present, extract Brand DNA directly:

- Inspect `brand/`, `assets/brand/`, `design-system/`, or similar
- Open the primary symbol SVG and analyze: stroke widths used, corner radii, terminals, color count, optical corrections visible in path data
- Inspect any wordmark for type pairing hints (informs icon weight choice)
- Look at app screenshots for current UI tone
- If a design-tool MCP is available (Figma, Pencil, etc.), use it instead of raw filesystem inspection — see [`design-tool-integrations.md`](design-tool-integrations.md)

If no logo SVG is available but a raster (PNG / JPG) version exists, extract what is observable (color count, approximate proportions, stroke style) and explicitly mark the rest as a labeled assumption.

Output an extracted Brand DNA summary in the response (`Brand DNA source: extracted from brand/primary-symbol.svg`). Ask the user to confirm before proceeding. Optionally write the result to `./brand/brand-dna.md` so future runs can use Mode 1.

### Mode 3: Ask user directly

When no logo or brand assets exist, run a guided conversation:

- Geometric alphabet preference (e.g., "all geometric, all rounded, mixed")
- Stroke vs filled preference (filled, outlined, both)
- Stroke weight if outlined (e.g., 1.5pt / 1.75pt / 2pt)
- Corner treatment (sharp, slightly rounded, very rounded)
- Terminal style (square / round / cut)
- Color count (monochrome, 2-color, multi-color)
- Reference brands user admires (extract DNA from them as a starting point)

Output a Brand DNA proposal and ask for confirmation. State unanswered dimensions as labeled assumptions. Optionally write the confirmed proposal to `./brand/brand-dna.md` so future runs can use Mode 1.

## Canonical `brand-dna.md` Structure

```markdown
# Brand DNA — {{Project Name}}

Generated: {{date}}
Source: {{hand-written / extracted from {{asset path}} / interactive intake / external tool name}}

## Geometric Alphabet
- Primary: {{primitives, e.g., "perfect circle, vertical/horizontal lines, 45° diagonals"}}
- Avoided: {{primitives explicitly excluded}}

## Stroke Language
- Weight: {{e.g., "1.75pt at 24px reference grid"}}
- Contrast: {{e.g., "uniform" or "1pt thin / 2pt thick"}}
- Modulation: {{rules for when stroke varies}}

## Terminal Style
- Default: {{square / round / cut}}
- Exceptions: {{when terminal style varies}}

## Corner Treatment
- Outer radius logic: {{e.g., "2pt at 24px grid, scales with size"}}
- Inner radius logic: {{e.g., "match outer", "0", "half outer"}}

## Color Logic
- Color count in mark: {{e.g., 2}}
- Roles: {{primary / secondary / accent}}
- Tint behavior: {{"single-tint friendly" / "two-color required"}}

## Optical Correction Principles
- Overshoot: {{e.g., "circles overshoot square frame by 2%"}}
- Balance: {{e.g., "visual centering preferred over geometric centering"}}
- Weight perception: {{e.g., "diagonal strokes 5% thicker than orthogonal"}}

## Reference Marks
{{paths or links to canonical SVG files}}
```

## How Icon System Uses Brand DNA

Each Brand DNA dimension constrains a specific icon system rule:

| Brand DNA dimension | Icon system rule it constrains |
|---|---|
| Geometric alphabet | Available primitives for icon construction |
| Stroke language | Default stroke weight, contrast rules |
| Terminal style | Stroke endings across the set (must match) |
| Corner treatment | Corner radius logic per icon |
| Color logic | Whether icons are single-tint or duotone, accent rules |
| Optical correction principles | How small-size and visual-balance corrections are applied |

If Brand DNA is silent on a dimension, the icon system makes a labeled assumption and asks for confirmation.

## Failure Modes

- **Inventing DNA when assets exist** — always extract or read first
- **Treating DNA as suggestions** — these are constraints, not preferences
- **Mixing extracted + invented** without flagging — every dimension must be sourced
- **Skipping confirmation in Mode 2** — extracted DNA is a hypothesis until user confirms
